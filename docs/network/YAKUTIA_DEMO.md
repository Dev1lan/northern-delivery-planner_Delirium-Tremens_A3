# Демонстратор водной сети Якутии

Сценарий включает четыре схематических узла, два состава буксир–баржа и три заявки на 300 т. Длины, окна навигации, характеристики флота, причалы и тарифы заданы для эксперимента. Геометрия интерфейса схематическая. Обязательный минимум сценария составляет 55 т продовольствия. Карточки реальных судов, реальные допуски и подтверждённые ставки требуют отдельных источников.

## Запуск

Из корня проекта с Python 3.12.14:

```powershell
python -m pip install -r requirements.txt
python -m unittest discover -s tests
python -m experiments.run_yakutia --output results/yakutia_demo_run
python -m network.web --bundle results/yakutia_demo_run/bundle.json
python -m experiments.yakutia_resilience --output results/yakutia_resilience_run
```

Сайт открывается по адресу [127.0.0.1:8765](http://127.0.0.1:8765). Выберите C, откройте Нижнеянск и сдвиньте ползунок времени. Кнопка «Показать решение» показывает исходное размещение флота, смену варианта C на D и движение по расписанию. «Пересчитать вариант» заново проверяет выбранное изменение относительно C. При запуске без `--bundle` сайт рассчитывает демонстрацию при старте. Папку вывода для каждого нового прогона выбирайте отдельно.

## Контрольные расчёты

Одинаковые заявки и базовый набор условных ставок. A и B сравнивают эффект разрешения межбассейновой перегонки при снятом ограничении причала. B и C показывают эффект ограничения одного причала. D добавляет второй причал как лучшее из трёх проверенных изменений в этом сценарии.

| Вариант | В срок, т | Всего, т | Критичных в срок, т | Дефицит минимума, т | Недовоз, т | Порожний пробег, км | Очередь, ч | Стоимость, DEMO |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| A · без морской перегонки | 75 | 75 | 25 | 30 | 225 | 10 | 0 | 7 144,33 |
| B · с перегонкой, без ограничения причала | 205 | 205 | 80 | 0 | 95 | 22 | 0 | 6 362,41 |
| C · с перегонкой и одним причалом | 140 | 190 | 80 | 0 | 110 | 22 | 5,37 | 7 374,08 |
| D · с перегонкой и двумя причалами | 205 | 205 | 80 | 0 | 95 | 22 | 0,5 | 6 478,03 |

Все четыре варианта проходят проверку схемы v3 и повторный физический аудит. В C и D одинаковое число рейсов. При переходе от C к D оценка снизилась на 896,05 DEMO с учётом заданной цены альтернативной доставки недовоза. В модели отсутствует стоимость строительства или аренды дополнительного причала.

Отчёт сохраняет входы, правила допуска, параметры поиска, хэши, результаты по пяти стратегиям и три набора тарифов. На базовых ставках `NETWORK_COST` и `NETWORK_REPOSITION` выбрали один план для C. В отдельном тесте при одинаковых 100 т в срок `NETWORK_COST` выбирает состав со стоимостью 15 DEMO против 150 DEMO. Стратегия сравнивает стоимость внутри ограниченного эвристического поиска, сохраняя найденный уровень обслуживания и приоритет социальных минимумов. При отсутствии тарифа альтернативной доставки для части остатка цена получает статус `PARTIAL`.

При испытании устойчивости на D ухудшение глубины дало 187,812 т в срок, задержка состава — 144,823 т, дополнительная заявка — 230 т в срок при росте спроса с 300 до 340 т. Два случая потребовали вмешательства из-за изменений, затронувших уже начатый рейс. Это сценарный анализ без вероятностей событий. Для четырёх узлов на рабочем компьютере один расчёт занял около 0,4 с с тремя заявками и около 1,1 с с девятью. В этих запусках сработал предел поиска `SEARCH_LIMIT`.

## Интерфейс и контракт

[Полный API-контракт для фронтенда](API_CONTRACT.md).

- `GET /api/demo` возвращает тот же набор входов, сравнений и результатов, который использует сайт. `POST /api/plan` повторяет расчёт.
- `GET /api/state?variant=C&moment=2026-07-01T00:00:00` возвращает суда, состояния причалов и очереди. `GET /api/port-load` принимает `variant`, `port`, `start`, `end`.
- `GET /api/compare?from=C&to=D` возвращает разницу метрик. `GET /api/improvements` возвращает проверенные альтернативы с результатами аудита.
- `GET /api/explain?variant=C&voyage=1` возвращает фактический маршрут, выгрузку, срок, стоимость и проверенные ограничения. Альтернативы на уровне отдельного рейса в этом расчёте не экспортируются.
- `POST /api/what-if` принимает `{"preset":0}` либо один объект `{"change":{...}}` в формате `network.analysis.change_scenario`. Исходный вариант C сохраняется. В интерфейсе доступны три портовых изменения. В API также доступны смена старта или состава флота, изменение объёма и срока заявки, закрытие участка и переключение морской перегонки.
- `expires_at` опционально ограничивает время завершения выгрузки. Если сохранённое физическое расписание содержит выгрузку после истечения срока, `cargo_condition` показывает физический, пригодный и просроченный тоннаж. Просроченный груз не засчитывается в социальный минимум.
- Сценарии с типом `REAL` или `MIXED` требуют источников для соответствующих записей. Морской переход требует подтверждённый допуск обоих судов и явно разрешённый состав. Сценарный допуск предназначен для синтетики.

Сайт в этой ветке запускается отдельно. Для объединения с существующей картой Якутии и экраном `/yana` нужны исходники этой карты. В текущем демонстраторе груз проходит маршрут одним составом. Перевалка между составами, реальный реестр флота, импорт CSV/Excel и сетевой ML остаются за пределами этой реализации.
