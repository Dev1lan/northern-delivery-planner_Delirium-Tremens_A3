# Инженерный план эксперимента с тремя портами

Этот документ описывает первоначальную постановку. Реализация 3.0.0, её интерфейс и результаты описаны в [документации сетевого планировщика](../network/README.md).

Текущее ядро назначает пару буксир–баржа на фиксированную цепочку и освобождает оба ресурса после возвращения. Маршрут A → B → C требует состояния местоположения, односторонних переходов и другой проверки ресурсов. Реализацию стоит вынести в `network_experimental/` с отдельными входами и аудитором. План ниже задаёт границы первого проверяемого прототипа.

| Объект | Данные и правила |
|---|---|
| Порт и переход | Синтетические порты A, B, C. Направленные дуги, километры, скорость, глубина и календарь закрытий по направлению |
| Физический ресурс | `resource_id`, `current_port`, `available_at`, тип, осадка и характеристики. Состав разрешено собрать из совместимых ресурсов в одном порту |
| Заявка | Порт погрузки и разгрузки, тип, готовность, срок и остаток массы |
| Событие | Погрузка, переход, разгрузка или порожний перегон. Интервал занятости обоих физических ресурсов и конечный порт |

Для первого прототипа фиксировать состав на всём переходе. После разгрузки освобождать оба ресурса в порту назначения. Выбирать среди прямых допустимых грузовых переходов и порожних перегонов, которые открывают доступ к конкретной готовой заявке. Сравнивать варианты по обеспечению и своевременной доставке с учётом времени перегона. Стоимость появляется только при заданных тарифах.

Аудитор восстанавливает порт каждого ресурса по событиям. Следующий интервал может начаться только после освобождения обоих ресурсов и в том же порту. Для каждого перехода аудитор проверяет проходимость, окно, осадку, грузоподъёмность и баланс заявок. Сетевой прототип может использовать чистые проверки глубины и массы после явного описания их интерфейсов. Исторические результаты линейного ядра служат отдельной регрессией.

Критерии приёмки: A → B → C с двумя грузами и без второго груза, обоснованный порожний перегон, запрет погрузки в неправильном порту, закрытый или слишком мелкий участок, конфликт буксира или баржи, баланс при частичной разгрузке. Начальный порт и каждый переход должны следовать из входов. Сопоставление синтетических портов с реальными пунктами загрузки требует данных перевозчика.
