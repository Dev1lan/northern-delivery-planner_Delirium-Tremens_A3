# Вход сценария и предварительная проверка

Сценарий — каталог с обязательными `cargo.csv`, `units.csv`, `conditions.csv` и отдельным JSON конфигурации маршрута. `python scenario_validation.py --scenario data/demo/scenario --config scenario_config.json` проверяет входы и возвращает итоговые суммы. Ошибка вызывает `ScenarioValidationError` с идентификатором или датой и ненулевой код команды. Тот же контроль применяется при `optimizer.load`, до запуска `optimizer.simulate` и через адаптер.

Проверяются уникальность идентификаторов, концы и непрерывность линейного маршрута, связи партий с планами при наличии планов в конфигурации, допустимые категории, идентификаторы буксиров и барж, числовые значения, скорости и производительность, корректность дат и окон доступности, осадки и глубины. Если рядом есть `vessels.csv`, его идентификаторы и роли дополнительно сверяются с составами. Отсутствие необязательного судового справочника отражается `vessel_links_checked: false`.

Календарь обязан содержать строку для каждой пары календарная дата × участок с `start` по `end` включительно. Явное закрытие — `is_closed=1`; отсутствующая строка — ошибка, а не признак закрытия. Дополнительные дни допускаются. Условия, которых не хватает при непосредственном вызове расчёта прохода, тоже вызывают ошибку.

Масса суммируется по `cargo_type` и, при наличии `plan_id`, по планам. Для независимой проверки баланса положите в каталог сценария `expected_cargo_totals.csv` с колонками `cargo_type,volume_t` и `expected_plan_totals.csv` с колонками `plan_id,volume_t`. Идентификаторы и суммы должны совпадать с партиями. Для архивных сценариев проекта, перечисленных в `data/scenario_manifest.csv`, контрольные суммы берутся из планов конфигурации и `demand_scale`. При загрузке непустого сценария отсутствие контрольной суммы по категориям вызывает ошибку; если у партий есть `plan_id`, обязательна и контрольная сумма по планам. Низкоуровневая `validate_inputs` без этих сумм возвращает флаги `category_totals_checked` и `plan_totals_checked` равными `false`; она не заменяет полную проверку каталога. Само совпадение сумм не подтверждает правильность исходного спроса.

Модель использует даты без смещения часового пояса. В конфигурации `start` и `end` — даты в 00:00; последняя допустимая готовность заявки, согласно существующему аудиту, — `end` в 00:00. Доступность состава — полуоткрытый интервал `[available_from, available_to)`. Скорости и производительность положительны; неизвестное значение нельзя заменять нулём или NaN. Пустые списки заявок и флота допустимы как крайние случаи. Проверка не сертифицирует реальную пригодность судна или истинность сценарных данных.
