## Что обнаружено

Исторические 607 рейсов прошли повторный независимый аудит. Остаток 182 989,609 т по 35 заявкам. У 34 из них рейсов нет. По типам остаток: уголь 107 949,609 т, топливо 41 280 т, нефть 30 179 т, газовый конденсат 2 221 т, продовольствие 1 360 т. Использовано по 38 буксиров и барж.

- Для 19 заявок даже оптимистичный граф с осадкой при загрузке 1 кг исключил прямой рейс одним допустимым составом. Такая проверка разрешает разные проходимые дни на разных рёбрах, поэтому может доказать отсутствие пути, но найденная связность сама по себе не доказывает выполнимость.
- Для 13 заявок отсутствует маршрут с допуском одного совместимого состава. Для трёх оставшихся заявок причина не установлена. Исторический поиск не экспортировал след каждого кандидата.
- Изолированные проверки дали 6 447,390 т для Z001, 240 т для Z025 и 1 000 т для Z026. Использовался бюджет 1 с на заявку, расширенный список кандидатов и тот же флот с теми же физическими ограничениями. Пустой результат пробы означает отсутствие найденного рейса.
- Для каждой заявки с остатком проверены пересечения окон буксира и баржи между исходными рейсами. Дополнительного рейса при сохранении всех 607 операций с их временем и стартовыми портами не найдено. Генератор вставок ограничен имеющимся маршрутизатором и ранними вариантами времени.
- При пересборке до 24 терминальных рейсов проверены 22 физически допустимых предложения. Замена состава в рейсе Z009 на 500 т сохранила тоннаж, снизила порожний ход на 166 км и условную стоимость на 194 220 ₽. Изменённое расписание прошло аудит и экспортировано отдельно.
- Для простаивавшего флота отчёт указывает базу, класс, осадку, доступность, совместимые заявки и достижимость порта погрузки по оптимистичной оценке. Отдельно фиксируются положительные свидетельства из проб. Отсутствие свидетельства оставляет результат неопределённым.
- Для межбассейновых заявок диагностирован прямой рейс. Перевалка требует отдельного доказательства выполнимой цепочки. Для передачи в такой модуль нужны порт стыковки, тоннаж партии, время готовности после выгрузки, допустимые составы следующего плеча и учёт причалов и конечного дедлайна.

## Изменения

- При включённом восстановлении часть списка кандидатов отведена другим комбинациям заявки и текущего порта состава. Лимит пар по заявке учитывает класс и порт. Сохраняются счётчики подробных проверок, физически построенных, отобранных и эвристически отсеянных вариантов по заявке.
- Быстрый начальный план с перегонкой строится до расширенного поиска расписаний. Бюджет времени общий. Старый путь расчёта доступен по умолчанию.
- Исходный `NETWORK_COST` формирует опорный тоннаж из предварительного поиска и после достижения этого уровня ставит цену выше дополнительной доставки. В режиме восстановления после достижения опорного уровня выше стоят социальные минимумы, своевременный и общий тоннаж, затем стоимость. Штраф за остаток вычисляется по переданным тарифам. Поиск эвристический.
- `critical_category` влияет на отчёт о критичных грузах. Обязательные минимумы задаются отдельно в `social_requirements`. Локальный конвертер `other_data/yakutia_real/build_scenario.py` передаёт пустой список. Ядро сохраняет `NOT_CONFIGURED`. Тест подтверждает выполнение явно заданного минимума и его сохранение в локальном ремонте.
