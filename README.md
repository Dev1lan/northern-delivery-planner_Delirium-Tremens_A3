# Delirium Tremens — Оптимизация Северного завоза в Якутии

**Кейс А3: «Как выбрать конкретное улучшение перевозок»**

Разработали исследовательский прототип для оптимизации речных грузоперевозок в Якутии. Пилотное направление — река Яна, с возможностью дальнейшей адаптации к другим речным маршрутам республики.

### Основные результаты

На 114 парах синтетических сценариев OPTIMIZED превзошёл FCFS по доставленному в срок тоннажу в 114 случаях.

- Средний прирост доставки в срок: **8 410,333 т на сценарий**.
- Средний относительный прирост: **323,118%**.
- Среднее увеличение общего доставленного тоннажа: **2 183,790 т**.
- Нарушений ограничений в 228 проверенных расписаниях: **0**.

Результаты относятся к синтетическим сценариям и не являются прогнозом фактического эффекта для перевозок в Якутии.

## Ввод

Исследовательский прототип для сравнения правил перевозок по заданной линейной речной цепочке. Демонстрационный маршрут — Нижнеянск — Усть-Куйга. Заявки, флот, осадки и ежедневные глубины в демонстрации синтетические или предположительные. **Это не система управления судоходством и не прогноз фактического завоза.**

Математическая логика алгоритма **2.1.0** сохранена: сначала максимизируются тонны, доставленные вовремя, затем общий доставленный тоннаж и при равенстве минимизируется число рейсов. Эвристика с ограниченным локальным поиском не гарантирует глобального оптимума. Хэши функций зафиксированы в `algorithm_invariants.json` и проверяются тестом.

## Запуск

Проверенная среда — CPython 3.12.14. Алгоритм использует стандартную библиотеку; для проверки JSON Schema и тестов установите закреплённые зависимости:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python scenario_validation.py --scenario data/demo/scenario --config scenario_config.json
python -m experiments.demo_check
python -m unittest discover -s tests -p "test*.py" -v
```

На macOS/Linux активация: `source .venv/bin/activate`. `experiments.demo_check` запускает FCFS и OPTIMIZED, проверяет схему и аудит и сравнивает полные результаты с `results/demo/`. Эталоны заменяются только явной командой `python -m experiments.demo_check --write`. Среда описана в [docs/ENVIRONMENT.md](docs/ENVIRONMENT.md).

В демонстрации каждая стратегия доставляет **1 156 т вовремя и всего**, выполняя 11 рейсов. Это проверка совместимости и воспроизводимости, не оценка реальных перевозок.

## Контракт и критичные грузы

```python
from result_adapter import run_scenario
from critical_cargo import compare_critical_cargo

fcfs = run_scenario('data/demo/scenario', strategy='FCFS', scenario_id='demo')
optimized = run_scenario('data/demo/scenario', strategy='OPTIMIZED', scenario_id='demo')
comparison = compare_critical_cargo(fcfs, optimized)
print(optimized['metrics'])
print(comparison['warnings'])
```

Или `python result_adapter.py --scenario data/demo/scenario --strategy OPTIMIZED --output result.json`. Контракт 1.0.0 и единицы описаны в [docs/RESULT_CONTRACT.md](docs/RESULT_CONTRACT.md), схема — [result.schema.json](result.schema.json). При ошибке входов или аудита расчёт прерывается.

Категории `food` и `food_extended` проверяются как критичные по умолчанию. При снижении общей или своевременной доставки относительно FCFS возвращается `CRITICAL_CARGO_DECREASE`; список можно задать явно. Сравнивать нужно результаты одного сценария: одинаковый идентификатор не доказывает идентичность входных файлов. Отсутствующая категория отмечается `not_present`.

## Полный архив и проверка хэшей

Для полного локального проекта доступны команды:

```powershell
python -m experiments.verify_manifest
python -m experiments.verify_final_reproducibility
```

Первая проверяет исходные манифесты и сохранённые SHA-256 без их перезаписи. Исторические имена исходников сопоставляются с неизменённым снимком в `release_2.1.0/`; для более раннего оптимизатора используется `results/provenance/optimizer_previous.py`. Вторая заново рассчитывает и сравнивает все 114 пар расписаний. Эти проверки требуют полного локального архива, который не включён в GitHub. Экспериментальные скрипты запускаются как модули `python -m experiments.<имя>`; полные запуски могут перезаписать результаты в `results/`. Генератор по умолчанию пишет в отдельный `data/generated/`, сохраняя исходные входы.

## Данные и ограничения

Предварительная проверка и обязательные контрольные суммы описаны в [docs/SCENARIO_INPUTS.md](docs/SCENARIO_INPUTS.md). Отсутствующая строка условий на дату и участок — ошибка, а не закрытие.

Обе стратегии получают заявки и точный сценарный календарь глубин и закрытий: это **планирование при полной информации**, не испытание прогноза реального диспетчера. Проверяются модельные осадки, глубины, тоннаж, время и занятость ресурсов. Не моделируются фактическая гидрология, погода, лёд, тяга и класс судна, общая очередь причалов, стоимость и разрешения. Приоритет конкретной категории не включён в целевую функцию.

На 114 парах синтетических сценариев средний прирост своевременного тоннажа к FCFS составлял 8 410,333 т, медианный — 8 400,681 т, средний относительный — 323,118%; выигрыш наблюдался в 114 парах. Это результаты полного сценарного эксперимента, не измеренный эффект на Яне. В части сценариев общий тоннаж продовольствия уменьшился: [docs/critical_cargo_report.md](docs/critical_cargo_report.md). Происхождение и статус исходных сведений — [docs/PUBLIC_SOURCES.md](docs/PUBLIC_SOURCES.md).
