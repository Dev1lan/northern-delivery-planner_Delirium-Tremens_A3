# Данные для сценарной модели доставки по Яне

> Обновление: итоговый оптимизатор и новые результаты описаны в `OPTIMIZER_README.md` и `optimization_report.md`. Архивные CSV в `data/` и нижеописанный отчёт старой эвристики сохранены. После исправления генератора воспроизводимость нового набора проверяйте в свежем каталоге, как указано в `OPTIMIZER_README.md`; для проверки сохранённого архива используйте `python validate.py --skip-reproducibility`.

Пакет сравнивает FIFO с эвристикой ранних сроков на участке Нижнеянск — Северный — Усть-Куйга. Реальные показатели всей Яны сохранены отдельно. Эвристика не является доказанно оптимальным алгоритмом.

## Что подтверждено и что создано

Подтверждены сводные показатели на 29 сентября и нормативные параметры двух участков. Есть локальные измерения глубины на 25 и 29 сентября. Характеристики трёх проектов барж проверены в каталоге ЛОРП; их работа на пилоте в 2026 году не подтверждена.

Объёмы 30 000 т угля, 4 500 т сырой нефти, 90 и 60 т продовольствия переписаны из ранее индексируемых приложений № 3, 4 и 7. Прямой доступ к ГАРАНТу при этой проверке — 403. Поэтому это предварительные плановые ориентиры с verification=INDEXED_ONLY_NOT_PRIMARY_VERIFIED, а не полностью проверенный первичный вход. Их использование и направление всего объёма из Нижнеянска — сценарные гипотезы. В исходном плане origin пуст.

Все суда с идентификаторами B_* и T* вымышленные. Их осадки, скорости, допустимая полезная загрузка, совместимость, доступность, параметры обработки, даты и приоритеты партий, ежедневные глубины — сценарные значения. Допустимость относится к этой модели. Она не подтверждает возможность реального плавания таких проектов с указанными осадками.

## Как обеспечивается совпадение агрегатов

В data/actuals.csv хранятся 148 860 / 122 520 / 113 470 / 89 030 т всей Яны. Три calibration_stage_allocations_r*.csv дают разные условные разбиения на партии с одинаковыми остатками 26 340 / 9 050 / 24 440 / 89 030 т. Это арифметическая сверка при явно включённой гипотезе вложенной цепочки. Источник не доказывает, что все четыре показателя отслеживают одни и те же партии. Ни одна такая партия не получает реальное судно или географическую точку.

Рейсы пилота не подгоняются под 89 030 т. Данных для транспортной калибровки пилота нет. Это незавершимая достоверно часть пункта 7 ТЗ; минимальный рабочий результат — физически согласованная демонстрация на объявленных допущениях. Нельзя называть её реконструкцией навигации или доказательством реального эффекта.

## Генерация и проверка

Требуется Python 3.10 или новее. Зависимости устанавливать не нужно. Из папки пакета:

```powershell
python generate.py
python validate.py
python analyze.py
python sensitivity.py
```

Если команда python на этом компьютере не работает, используйте bundled runtime:

```powershell
& 'C:\Users\dev1l\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe' generate.py
& 'C:\Users\dev1l\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe' validate.py
```

Seed задан в scenario_config.json. Валидатор повторяет генерацию во временную папку и сравнивает SHA256 всех CSV. Скрипты берут пути относительно собственного расположения. Запуск не требует ручной правки CSV. Чтобы заменить реку, измените узлы, участки, длины, даты, профили глубин, спрос, планы и флот в JSON. В вычислительном алгоритме названия рек и расстояние 324 км не зашиты. Минимальная версия поддерживает упорядоченную линейную цепочку; для ветвящейся сети потребуется отдельный поиск пути и назначение заявок маршрутам.

## Как загрузить в симулятор

```python
import json
from pathlib import Path
from generate import load_scenario, simulate

root = Path(__file__).resolve().parent
config = json.loads((root / 'scenario_config.json').read_text(encoding='utf-8'))
cargo, units, conditions = load_scenario(root / 'data/scenarios/r1_baseline_central_central')
trips, metrics = simulate(config, cargo, units, conditions, 'baseline')
print(metrics)
```

Для оптимизированной эвристики замените последний аргумент на `optimized_heuristic`. Обе стратегии получают одинаковые внешние данные; внутри диспетчеризации случайность отсутствует.

## Сценарии и результаты

Создаются 108 вариантов: 3 seed × 4 внешних условия × 3 глубины × 3 сдвига готовности. Для каждого рассчитаны обе стратегии, всего 216 расписаний. Полные входы и рейсы — в data/scenarios. Центральный вариант первого seed продублирован непосредственно в data для удобного первого запуска. Метрики всех вариантов — data/comparison.csv.

Стресс A ограничивает полезную загрузку каждого состава на 20%, сохраняя исходную кривую осадки; это сокращение провозной способности, не сокращение фактического числа судов. Стресс Б увеличивает каждую партию на 30%, сохраняя даты и флот. Стресс В закрывает оба участка на 10 дней раньше. После каждого изменения рейсы пересчитываются полностью.

Флот возвращается в исходный пункт перед освобождением ресурсов. Если завершить возвращение до закрытия нельзя, рейс не назначается. Ночные ограничения и отдельная очередь причалов не моделируются. Каждому составу сценарно предоставлено своё место обработки. Грузы разных типов не смешиваются в одном рейсе; сухогрузные баржи имеют условное разрешение на уголь и продовольствие с обработкой между рейсами.

Результаты могут быть хуже, равны или лучше FIFO. Не выбирайте один удачный seed для презентации: используйте все варианты, показывайте диапазон и случаи ухудшения. Стоимость не рассчитывается.

analyze.py создаёт experiment_summary.md из всех 108 пар. sensitivity.py независимо пересчитывает и проверяет ещё 54 расписания при изменении неизвестных скоростей, осадок, обработки и запаса под днищем. Эти дополнительные результаты — в sensitivity_results.csv и sensitivity_report.md; они не входят в manifest основной генерации и не изменяют её входы.
