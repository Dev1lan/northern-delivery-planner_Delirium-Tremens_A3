# ML-модуль для матмодели Case A3 (Северный завоз, Яна)

Модуль обучен на результатах матмодели команды (`optimizer.py`, алгоритм 2.1.0) и отдаёт ответ в формате контракта результата 1.0.0 (`result.schema.json`). Собственной физики в модуле нет: рейсы, осадки, глубины и аудит считает только матмодель. Файлы матмодели не изменены.

> Данные синтетические, метки ставит матмодель (эвристика, не глобальный оптимум). Это не реальные диспетчерские решения и не факты о Яне. Модель не готова к эксплуатации.

## Установка и запуск

Папку `ml/` положить внутрь `Case_a3/` (рядом с `optimizer.py`). Если она лежит в другом месте, задать `A3_ROOT=<путь к Case_a3>`.

```bash
pip install -r ml/requirements.txt
cd ml
python predict.py --scenario ../data/demo/scenario --output result.json --recommendation-output rec.json
python check_contract.py            # проверка на всех сценариях проекта, ~3 мин (нужен архив, см. ниже)
```

```python
from predict import run_recommended
result, rec = run_recommended('data/scenarios/r1_baseline_central_central', scenario_id='yana_001')
```

Режим «лучшая из трёх» — считает все стратегии матмоделью и возвращает лучшую по её целевой функции:

```python
from predict import run_best_of_all
result, summary = run_best_of_all('data/demo/scenario')   # CLI: python predict.py --scenario ... --best-of-all
```

`result` — результат лучшей стратегии по контракту 1.0.0, `summary` — метрики и время расчёта всех трёх, выигрыш относительно `OPTIMIZED` и прогноз ML для сравнения. Выбор делает не нейросеть, а сравнение рассчитанных результатов, поэтому потерь относительно лучшей из трёх нет. Цена — время расчёта трёх стратегий вместо одной (две простые считаются быстро). Режим работает и при отключённом ML.

- `result` — объект контракта 1.0.0: `schema_version`, `scenario_id`, `strategy`, `metrics`, `trips`. Его строит `result_adapter.run_scenario`, модуль дополнительно проверяет его по `result.schema.json`.
- `rec` — рекомендация ML: стратегия, `confidence`, прогноз тоннажа вовремя по каждой стратегии, признаки, итог проверки.

Схема контракта запрещает лишние поля (`additionalProperties: false`), поэтому `confidence` и прогноз **не вкладываются** в объект результата, а идут отдельным объектом или файлом.

Пересборка с нуля (8 ядер):

```bash
python generate_data.py synthetic --families 1000   # ~25 мин: 2000 сценариев вокруг Яны × 3 стратегии
python generate_data.py universal --families 1000   # ~1,5–2 ч: 2000 сценариев на произвольных маршрутах
python generate_data.py stress --families 60 --variants 1   # ~20 мин: 7 стресс-режимов × 60
python generate_data.py archive     # ~3 мин: 108 архивных сценариев + demo (нужен полный архив data/scenarios)
python train.py                     # ~1 мин; с PyTorch создаёт model.pt
python generate_data.py refeaturize [--archive-root <dir>]  # только пересчёт признаков, метки не трогаются
```

Полный архив сценариев в GitHub не лежит. Проверку можно запустить на копии из материалов жюри:

```bash
python check_contract.py --archive-root "../JURY_SUBMISSION/Расчёты/data/scenarios" --comparison "../JURY_SUBMISSION/Расчёты/comparison_final.csv"
```

## Как это работает

1. Из входов сценария (`cargo.csv`, `units.csv`, `conditions.csv`, конфигурация) считаются 19 признаков — до любого расчёта. Четыре из них — «жидкостная» оценка: грубый посуточный баланс «сколько тонн флот успевает привезти к срокам» при трёх порядках обслуживания (`a3_bridge.fluid_features`). Она не строит расписание и не запускает стратегии матмодели.
2. Прогнозная нейросеть (ансамбль из 5 MLP 2×64) предсказывает поправку к жидкостной оценке и выдаёт долю тоннажа вовремя для каждой стратегии с интервалом ≈90% (`on_time_share_interval90`).
3. Нейросеть-классификатор (PyTorch, MLP с двумя скрытыми слоями) оценивает, какая стратегия лучшая. Запускается её выбор только при уверенности не ниже порога, подобранного на валидации по потерям тоннажа, и только если выигрыш на валидации устойчив; иначе — `OPTIMIZED`. Сейчас порог равен 1.01, то есть всегда запускается `OPTIMIZED` (см. результаты).
4. Если сценарий вне обучающего распределения, не хватает данных или ML отключён (`A3_ML_DISABLED=1`), берётся `OPTIMIZED`, `action = FALLBACK_TO_OPTIMIZER`, прогноз не выдаётся.
5. Расписание строит матмодель. Её аудит (`validate.audit`) прерывает расчёт при любом нарушении, поэтому нейросеть не может нарушить ограничения по осадке, грузоподъёмности, занятости и навигации.

Метка для обучения — целевая функция матмодели: тоннаж вовремя, затем общий тоннаж, затем меньше рейсов; при полном равенстве — более простая стратегия.

## Результаты (`metrics.json`, `contract_check.json`)

Обучение: 4000 синтетических сценариев (2000 семейств × 2 варианта), разбиение 70/15/15 по семействам (2800/600/600). Половина — сценарии вокруг Яны (`dataset_synthetic.csv`), половина — произвольные линейные маршруты (`dataset_universal.csv`): 60–2500 км, 1–5 участков со своими глубинами, 1–12 составов до трёх типов груза, навигация 60–170 суток. Проверка: 108 архивных сценариев проекта и demo, 420 стресс-сценариев; в обучении они не участвовали.

**Формат ответа.** На всех 109 сценариях проекта ответ проходит `result.schema.json`, суммы по рейсам сходятся с метриками, `violations = 0`. Тоннаж совпадает с сохранёнными результатами проекта: 24 строки `comparison_final.csv` и `results/demo/optimized.json` (полное совпадение объекта).

**Прогноз доли тоннажа вовремя** — основная польза модуля. Средняя абсолютная ошибка в долях спроса; тест разделён на сценарии Яны (316) и произвольные маршруты (284), которых модель не видела:

| Модель | Яна, OPTIMIZED | Другие маршруты, OPTIMIZED | Архив, OPTIMIZED | Яна, 3 стратегии | Другие маршруты, 3 стратегии |
|---|---|---|---|---|---|
| Среднее по обучающей выборке | 0,231 | 0,265 | 0,236 | 0,231–0,273 | 0,265–0,316 |
| Жидкостная оценка без ML | 0,073 | 0,116 | 0,003 | 0,073–0,147 | 0,116–0,178 |
| RandomForest | 0,035 | 0,063 | 0,004 | 0,035–0,049 | 0,063–0,085 |
| Градиентный бустинг | 0,029 | 0,060 | 0,009 | 0,029–0,046 | 0,060–0,079 |
| MLP без жидкостных признаков | 0,048 | 0,071 | 0,011 | 0,048–0,053 | 0,071–0,082 |
| **Ансамбль MLP, поправка к жидкостной оценке** | 0,019 | 0,043 | 0,002 | 0,019–0,042 | 0,043–0,068 |

На произвольных маршрутах 90% ошибок для `OPTIMIZED` не больше 0,115, на Яне — 0,056. Интервал ≈90% накрывает факт в 94% сценариев Яны и в 88% сценариев других маршрутов (средняя ширина 0,172 и 0,229). Для `FCFS` и `EARLIEST_DUE` прогноз грубее. Это быстрая оценка до расчёта, не замена расчёта.

**Стресс-режимы ТЗ** (`a3_bridge.REGIMES`): параметры за пределами диапазонов вокруг Яны. После добавления произвольных маршрутов большинство таких сценариев модуль уже считает знакомыми.

| Режим | Ушло в fallback | Ошибка прогноза OPTIMIZED | Ошибка «среднего» | Накрытие интервала | Потери тоннажа, % спроса |
|---|---|---|---|---|---|
| Рост спроса (`demand_growth`) | 37% | 0,002 | 0,413 | 100% | 0,000 |
| Мало крупных партий (`few_large_lots`) | 10% | 0,011 | 0,301 | 97% | 0,012 |
| Дефицит флота (`fleet_deficit`) | 35% | 0,008 | 0,355 | 100% | 0,000 |
| Избыток флота (`fleet_surplus`) | 10% | 0,025 | 0,254 | 97% | 0,015 |
| Длинный маршрут (`long_route`) | 8% | 0,020 | 0,295 | 97% | 0,032 |
| Мелкий бар (`shallow_bar`) | 10% | 0,021 | 0,278 | 97% | 0,007 |
| Короткая навигация (`short_navigation`) | 32% | 0,019 | 0,232 | 100% | 0,000 |

Ошибка посчитана по всем сценариям режима, включая те, где модуль прогноз не выдаёт (fallback). Потери тоннажа — относительно лучшей из трёх стратегий. «Изменение числа пунктов доставки» не проверено: в матмодели один пункт назначения.

**Выбор стратегии.** Вокруг Яны он почти вырожден: правило «всегда OPTIMIZED» теряет 0,022% спроса. На произвольных маршрутах простая стратегия строго выигрывает у `OPTIMIZED` примерно в 4% сценариев, правило «всегда OPTIMIZED» теряет в среднем 0,256% спроса (в худшем сценарии теста — 4022 т). Классификатор без защиты эти случаи не ловит и в сумме теряет больше (0,488% спроса на всём тесте). Отклоняться от `OPTIMIZED` разрешено только при устойчивом выигрыше на валидации (парный бутстрэп); он не подтвердился, поэтому порог равен 1.01: модуль всегда запускает `OPTIMIZED`. Нулевые потери даёт только расчёт всех трёх стратегий с выбором лучшей.

**Вне распределения.** На тесте к оптимизатору уходит 3% сценариев, на архиве — 0%.

## Ограничения

- Все данные синтетические. Диапазоны варьирования (`a3_bridge.RANGES` вокруг `scenario_config.json` и `a3_bridge.UNIVERSAL` для произвольных маршрутов) — сценарные допущения ML-модуля, не данные о реальных реках.
- «Универсальность» ограничена тем, что считает матмодель: одна линейная цепочка «пункт отправления → пункт назначения», один пункт назначения, до ~220 ожидаемых рейсов за навигацию (на больших сценариях расчёт слишком долгий для разметки). Сеть с развилками не поддерживается.
- Архив проекта сделан тем же генератором, что и обучающие данные, поэтому малая ошибка на нём не говорит о точности на реальных перевозках.
- Жидкостная оценка — упрощение внутри ML-модуля (рейсы не дискретны, очереди не моделируются). Она используется только как признак.
- Признак `urgent_cargo_share` использует порог 14 суток — допущение модуля.
- `confidence` классификатора не откалиброван. Прогнозная сеть — sklearn `MLPRegressor`, классификатор — PyTorch.
- Тест `tests/test_algorithm_invariants.py` падает на Python 3.13/3.14 на нетронутых файлах: хэши AST в нём привязаны к CPython 3.12. Остальные тесты проходят.
- Модель не готова к эксплуатации.
