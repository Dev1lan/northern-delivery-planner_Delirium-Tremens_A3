# ML-модуль для матмодели Case A3 (Северный завоз, Яна)

Модуль обучен на результатах матмодели команды (`optimizer.py`, алгоритм 2.1.0) и отдаёт ответ в формате контракта результата 1.0.0 (`result.schema.json`). Собственной физики в модуле нет: рейсы, осадки, глубины и аудит считает только матмодель. Файлы матмодели не изменены.

> Данные синтетические, метки ставит матмодель (эвристика, не глобальный оптимум). Это не реальные диспетчерские решения и не факты о Яне. Модель не готова к эксплуатации.

## Установка и запуск

Папку `ml/` положить внутрь `Case_a3/` (рядом с `optimizer.py`). Если она лежит в другом месте, задать `A3_ROOT=<путь к Case_a3>`.

```bash
pip install -r ml/requirements.txt
cd ml
python predict.py --scenario ../data/demo/scenario --output result.json --recommendation-output rec.json
python check_contract.py            # проверка на всех сценариях проекта, ~3 мин
```

```python
from predict import run_recommended
result, rec = run_recommended('data/scenarios/r1_baseline_central_central', scenario_id='yana_001')
```

- `result` — объект контракта 1.0.0: `schema_version`, `scenario_id`, `strategy`, `metrics`, `trips`. Его строит `result_adapter.run_scenario`, модуль дополнительно проверяет его по `result.schema.json`.
- `rec` — рекомендация ML: стратегия, `confidence`, прогноз тоннажа вовремя по каждой стратегии, признаки, итог проверки.

Схема контракта запрещает лишние поля (`additionalProperties: false`), поэтому `confidence` и прогноз **не вкладываются** в объект результата, а идут отдельным объектом или файлом.

Пересборка с нуля:

```bash
python generate_data.py synthetic   # ~25 мин на 2 ядрах: 520 сценариев × 3 стратегии
python generate_data.py archive     # ~3 мин: 108 архивных сценариев + demo
python train.py                     # ~1 мин
```

## Как это работает

1. Из входов сценария (`cargo.csv`, `units.csv`, `conditions.csv`, конфигурация) считаются 15 признаков — до любого расчёта.
2. Нейросеть-классификатор выбирает стратегию: `FCFS`, `EARLIEST_DUE` или `OPTIMIZED`. Вторая нейросеть прогнозирует долю тоннажа, доставленного вовремя, для каждой стратегии.
3. Если сценарий вне обучающего распределения, не хватает данных или ML отключён (`A3_ML_DISABLED=1`), берётся `OPTIMIZED` — штатный оптимизатор. `action` тогда равен `FALLBACK_TO_OPTIMIZER`.
4. Расписание строит матмодель. Её аудит (`validate.audit`) прерывает расчёт при любом нарушении, поэтому нейросеть не может нарушить ограничения по осадке, грузоподъёмности, занятости и навигации.

Метка для обучения — целевая функция матмодели: тоннаж вовремя, затем общий тоннаж, затем меньше рейсов; при полном равенстве — более простая стратегия.

## Результаты (`metrics.json`, `contract_check.json`)

Обучение: 520 синтетических сценариев (260 семейств × 2 варианта), разбиение 70/15/15 по семействам. Проверка: 108 архивных сценариев проекта и demo, в обучении не участвовали.

**Формат ответа.** На всех 109 сценариях проекта ответ проходит `result.schema.json`, суммы по рейсам сходятся с метриками, `violations = 0`. Тоннаж совпадает с сохранёнными результатами проекта: 24 строки `results/comparison_final.csv` и `results/demo/optimized.json` (полное совпадение объекта).

**Выбор стратегии.** В этой матмодели он вырожден: `OPTIMIZED` лучшая в 519 из 520 синтетических сценариев и в 108 из 109 архивных. Классификатор поэтому всегда отвечает `OPTIMIZED` и ничем не лучше правила «всегда OPTIMIZED» (`DummyClassifier`): точность у обоих 100% на тесте и 99% на архиве, потери тоннажа нулевые. Единственные исключения — сценарии с очень малым спросом, где все стратегии довозят почти всё.

**Прогноз тоннажа вовремя** — единственное, где нейросеть даёт содержательный результат. Средняя абсолютная ошибка доли спроса:

| Модель | Тест (78) | Архив проекта (109) |
|---|---|---|
| Среднее по обучающей выборке | 0,12–0,18 | 0,18–0,21 |
| RandomForest | 0,051–0,061 | 0,029–0,049 |
| **MLP 2×32** | **0,045–0,053** | **0,030–0,031** |

Диапазон — по трём стратегиям. Ошибка 3–5 п.п. спроса: годится как быстрая оценка до расчёта, не как замена расчёта.

**Вне распределения.** На тесте детектор отправляет к оптимизатору 7,7% сценариев, на архиве — 1 из 109 (demo: 6 партий груза при 137–195 в обучении).

## Ограничения

- Обучающих сценариев мало (520), все на одном маршруте Нижнеянск — Усть-Куйга (324 км). Другой маршрут модуль распознаёт как выход за распределение.
- Диапазоны варьирования (`a3_bridge.RANGES`) — сценарные допущения вокруг `scenario_config.json`.
- Признак `urgent_cargo_share` использует порог 14 суток — допущение модуля.
- В среде сборки нет PyTorch, поэтому поставлены веса sklearn-MLP той же архитектуры (2 скрытых слоя, ReLU, кросс-энтропия, Adam). `python train.py --backend torch` создаст `model.pt`; этот путь написан, но не запускался. Прогнозная сеть в обоих случаях — sklearn `MLPRegressor`.
- Тест `tests/test_algorithm_invariants.py` на Python 3.13 падает на нетронутых файлах: хэши AST в нём привязаны к CPython 3.12. Остальные тесты адаптера и схемы проходят.
