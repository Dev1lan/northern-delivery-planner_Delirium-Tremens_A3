# Сетевой ML-прогноз (Якутия, ядро network 3.0.0)

Быстрая оценка до расчёта: какую долю тоннажа в срок даст каждая стратегия сетевого ядра и какую стратегию считать первой. Это не замена оптимизатора: расписание, проверку осадок и окон и аудит делает только `network`. Старая модель Яны (`ml/*.py`) не изменена.

```bash
ml/.venv/bin/python ml/network_ml/build_dataset.py --per-base 200 --workers 6   # ~11 мин, 3000 расчётов ядра
ml/.venv/bin/python ml/network_ml/train.py                                      # ~1 мин → model.joblib, metrics.json
ml/.venv/bin/python ml/network_ml/predict.py data/yakutia/yakutia_network.json
```

## Данные

- 600 сценариев × 5 стратегий = 3000 расчётов, все прошли `audit_result` (PASSED). Метка — `metrics.delivered_on_time_t / demand_t`.
- Три базы по 200 сценариев: `syn` (синтетическая сеть `data/yakutia/yakutia_network.json`), `real` (реальный сценарий 2026, 15–40% заявок и 25–60% флота), `deep` (вариант E1 «реки углублены» с той же подвыборкой). Возмущения: объёмы ×0,5–1,6, сдвиг сроков ±10 дней, глубины речных рёбер ×0,85–1,15.
- В каждой строке: версия ядра, коммит, политика поиска (`STANDARD`, 4–6 с), лимиты, причина завершения, аудит, время расчёта, отпечаток входа. `TIME_LIMIT` — 3,8% строк, помечены `time_limited = 1`. Обучение отбрасывает строки другой версии ядра и без аудита PASSED. Сведения о наборе — `data/DATASET_PROVENANCE.json`.

## Признаки (`features.py`, до расчёта)

Спрос и доли типов грузов, доля критичных; размер сети и флота, число совместимых пар, доля пар с морским допуском; доля тонн без пути, доля тонн, которым нужно море; доля тонн, для которых есть пара, проходящая весь путь по осадке порожней баржей и в полном грузу; средняя длина пути и окно навигации на пути; запас окна относительно времени хода; средняя дистанция перегона от баз буксиров до портов погрузки; грубая «жидкостная» провозная способность.

По стратегиям на отложенной выборке MAE доли: «С перегоном» 0,091, «По цене» 0,091, «Соцминимумы» 0,038, «Жадная» 0,035, «По очереди» 0,030.

Что это значит:

- Внутри реальной сети прогноз полезен: ошибка ~6% спроса, перенос с реального сценария на углублённый и обратно работает (R² 0,77–0,88).
- Выбор стратегии почти тривиален: «С перегоном» лучшая в 91% сценариев. Модель добавляет ~6 п. п. точности и снижает потери с 420 до 300 т.
- Перенос на чужую сеть не работает: обученная только на реальной сети, модель ошибается на синтетической на 32% спроса. Для новых акваторий нужны их расчёты в обучении.
- Полный реальный сценарий (65 заявок, 145 судов) больше любого обучающего: `predict.py` честно отвечает `OUT_OF_DISTRIBUTION` и не рекомендует стратегию. Для справки прогноз «С перегоном» 481 тыс. т против 547 тыс. т у ядра (E0) и 571 тыс. т против 563 тыс. т (E1). Чтобы закрыть полный масштаб, нужны полноразмерные сценарии в обучении (по 30–45 с на расчёт).

Сценарии — обучающие возмущения, а не факты; тарифы условные.
