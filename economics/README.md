# Финансовый модуль — речные перевозки по Яне

Дополнение к `northern-delivery-planner_Delirium-Tremens_A3`. Модуль рассчитывает стоимость **уже сформированного** расписания и не меняет `optimizer.py`, его целевую функцию, ограничения, хэши или контракт результата.

## Состав

- `cost_config.json` — тарифы, расход топлива и условные исходные данные.
- `cost_model.py` — расчёт стоимости отдельного рейса и всего расписания.
- `schedule_economics.py` — вызов существующего `result_adapter.run_scenario()` и формирование финансового отчёта.
- `cost_comparison.py` — сравнение отчётов разных стратегий одного сценария.
- `tests/test_cost_model.py` — базовые тесты финансовых формул.

## Установка в репозиторий

Скопируйте папку `economics/` в корень проекта рядом с `result_adapter.py`, `optimizer.py` и `scenario_config.json`. Исходные файлы проекта заменять не нужно.

Зависимости: только стандартная библиотека Python; дополнительные пакеты не требуются.

## Запуск

Из корня проекта:

```bash
python -m economics.schedule_economics \
  --scenario data/demo/scenario \
  --strategy OPTIMIZED \
  --output results/economics_optimized.json
```

Для FCFS:

```bash
python -m economics.schedule_economics \
  --scenario data/demo/scenario \
  --strategy FCFS \
  --output results/economics_fcfs.json
```

Сравнение:

```bash
python -m economics.cost_comparison \
  results/economics_fcfs.json \
  results/economics_optimized.json \
  --output results/economics_comparison.json
```

Тесты:

```bash
python -m unittest discover -s economics/tests -v
```

## Логика расчёта

Для каждого рейса:

1. Топливо: суммируется продолжительность каждого события движения `upstream` и `downstream`, умноженная на расход топлива состава в литрах в час.
2. Стоимость топлива: литры × цена одного литра.
3. Эксплуатация буксира и баржи: время от `loading_start` до `released_at` × суточная ставка / 24. Таким образом учитывается полный цикл, включая возврат порожнем.
4. Погрузка и выгрузка: перевезённые тонны × отдельный тариф за тонну для каждой операции.
5. Стоимость рейса — сумма перечисленных статей и явно заданных прочих расходов.

Для расписания суммируются стоимости всех рейсов. Стоимость тонны считается как общие затраты / `metrics.delivered_total_t`.

## Важные границы модели

- Вход — результат `result_adapter.py`: поля `trips`, `metrics`, `events`, `loading_start`, `released_at`, `volume_t`, `unit_id`.
- Используются события обоих направлений, которые формирует существующая модель рейса.
- Суточные ставки буксира и баржи в демонстрационном конфиге **не включают топливо и погрузочно-разгрузочные работы**. Если реальные тарифы будут включать эти расходы, конфигурацию нужно изменить, иначе возникнет двойной учёт.
- В расчёте пока нет постоянных расходов за сезон, ремонта, зарплат, страхования, портовых сборов, налогов, амортизации, стоимости хранения и стоимости недоставленного груза. Их нельзя добавлять без согласования состава затрат и исходных данных.
- Расход топлива задаётся по составу в целом (буксир + баржа), а не по каждому двигателю отдельно.
- Никаких предположений о реальной цене топлива или рыночных тарифах эти числа не выражают.

## Демонстрационные параметры

`cost_config.json` содержит условные значения: топливо 75 RUB/л, расход 28–50 л/ч в зависимости от состава и направления, эксплуатация буксира 35 000 RUB/сутки, баржи 15 000 RUB/сутки, обработка 250 RUB/т на погрузку и 250 RUB/т на выгрузку. Это только стартовые числа для проверки работы кода.

Все значения можно заменить в `cost_config.json`, не изменяя Python-код.

## Статус данных

В отчёте сохраняется `data_status: ASSUMED`. Не используйте демонстрационные результаты как оценку фактической себестоимости перевозок.
